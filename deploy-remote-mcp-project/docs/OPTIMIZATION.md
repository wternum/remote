# M/W 统一判读：本轮优化与证据

本文件描述当前实现，替代以前并列维护多套结论的优化记录。规则详情以 [标注模块说明](../src/vela/signals/README.md) 为准。

## 1. 本轮目标和边界

围绕双顶/双底回答：关键区域有哪些力量证据、是否扫位收回/诱多诱空候选、关键位或颈线突破后是否已回踩/反抽、是否真正收盘守住、何时失效。**不预测一定会回踩、不编造到达时间、不把证据计数当胜率。**

交易回测、确认引擎的19因子模型、数据库表与服务端API业务不变。`src/quant/flow.ts` 只调整连接时序和取消后的冷却处理；`src/runtime/` 修复浏览器代理分流。原始 `remote/`、`reference/`、`remote-project/` 未改。

## 3. 修复/统一的内容

1. **过早“已兑现”**：旧实现离开关键位1.5 ATR且超过12根就标完成；新回归用例在旧代码上实际失败。现改成颈线确认后的后续已收盘K真实触达延伸参考位，且未先失效，才显示「延伸位已到·不追」。不声称账户盈利。
2. **并列结论冲突**：删除 `keyLevelCall` 与阶段机各自组装一张卡的逻辑；关键位/颈线各一次生命周期，由最近状态事件选择当前主结论。晚发生的反向失效不能被旧颈线状态遮住。
3. **触碰被误当确认**：`reachedIdx` 与 `retestConfirmedAt` 分开。只碰到区带不显示“守住”；时间线用实际确认的收盘时点，不回填到第一次触碰。
4. **归并重复结构**：同方向、时间区间重叠、关键位接近或共用颈线时归并；不合并不同历史周期。原确认事件可在时间线查看。
5. **陷阱口径分裂**：测试扫位型/破位收回型保留来源差异，活跃观察窗统一12根。成交不足就写价格事实，而非断言真实被套/止损。
6. **旧形态被年龄过滤**：按最近事件而非单纯形态年龄决定活跃性；一个旧形态刚发生新颈线突破时仍可跟踪。已结束内容留在历史，默认不挤占主线列表。
7. **证据碎片化**：原成交反应、诱多、诱空、CVD独立条目并入同一形态；SMC为可选附加详情。普通支撑的触碰成交附在同一条背景记录。
8. **未收盘抖动**：即使预览开启，主结论/方向/目标也不受盘中价格改写，只增加独立提示；形成中逐笔变化在预览关闭时不重算历史。
9. **代码/说明不一致**：失效提示统一到实际0.2 ATR；回踩确认严格按≤0.9×缩量，不再用旧 `<1.2×` 条件声称“缩量守住”。均为标注层规则，不改原交易回测参数。
10. **快速切币CORS错误**：真实浏览器的符号切换回归抓到了中止请求误走浏览器上游兜底。现中止保持中止、统计JSON错误透传、HTML回退为503，不再直连无CORS接口。
11. **实时订阅等待历史**：WebSocket连接提前到历史统计回填之前；用户取消不再被当成5分钟上游故障。对应独立单测覆盖。
12. **历史看不到形态**：列表点选可临时聚焦其几何/标记，而不是只改变视口；这不会将过期状态复活，也不会延伸未来区带。

## 6. 验证范围与限制

- 新的提前完成回归实际先红后绿。
- TS套件验证规则/数据边界；浏览器套件使用**测试专用**REST/WS，检查真实Canvas、六段证据、定位、7控制项、重连、预览隔离、刷新、切币和手机。
- 真实市场诊断只证明这次输入下的运行性和不变量，不证明预测力、胜率或收益。
- 没有实现OFI、逐价Footprint、账户仓位、止损识别或自动下单。现有FlowBar为每根聚合总额，不能还原逐价成交分布。
- 纯静态Vite部署不能凭浏览器突破rubik的CORS限制：服务端代理不可用时明确降级，真实逐笔覆盖仍受网络与回补范围限制。
- 阈值是工程启发式。独立样本外验证交易效果是另外的任务，不把本轮测试冒充该验证。
