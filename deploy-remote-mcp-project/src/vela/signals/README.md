# 双顶 / 双底统一标注

当前主线：**一个 M/W 结构、一条可展开判读、一个阶段出口**。所有内容来自已加载的真实价格/成交数据或明确标识的价格事实；不下单、不输出校准胜率，不推断真实止损或参与者身份。

## 1. 用户看到什么

右侧「信号标注」默认打开「双顶双底」页签。

- 「正在跟踪」显示仍在观察的形态；「含历史」保留已结束记录。
- 点击一条记录展开完整证据并定位图表；点时间线可以定位到具体事件。
- 历史记录被点选后可以临时显示几何与标记，**不因此恢复为有效信号**；切换市场清除焦点。
- 每条记录有六段：当前结论、关键区域力量、真实成交证据、诱多/诱空、突破→回踩/反抽、参考位与失效。
- 辅助记录与显示设置分开。SMC 是同一形态的可选附加详情，不再独立刷多条记录。

七个显示控制（不是七种都独立生成记录）：

| ID | 显示项 | 默认 | 用途 |
| --- | --- | --- | --- |
| `doubleTop` | 双顶判读 | 开 | 完整 M 型判读及关联画布元素 |
| `doubleBottom` | 双底判读 | 开 | 完整 W 型判读及关联画布元素 |
| `keyLevelScenario` | 突破回踩区 | 开 | 控制同一形态的观察区带，不额外生成记录 |
| `keyLevels` | 支撑 / 阻力 | 关 | 普通摆动位背景，最近触碰的真实成交附在同条记录 |
| `retest` | 其他突破回踩 | 关 | 普通摆动位首次回踩，不替代 M/W 颈线路径 |
| `smartMoney` | 结构补充 | 关 | 在同一 M/W 详情显示现有 SMC 检测的命中事实 |
| `deltaImpulse` | 成交力度 | 关 | 既有真实成交异动/吸收候选/爆量；可选 OHLC 近似仅限辅助显示 |

原 `keyLevelFlow`、`bullTrap`、`bearTrap`、`cvdDivergence` 不再生成独立记录；其证据并入 M/W 的第三、第四段。配置使用 `pulsedesk.signal-annotations.v2`；首次读取会从 v1 迁移共有字段（方向开关、辅助项、总开关、回看、标签、几何、预览、近似），保留旧存储值供回退，不整体清空用户设置。

## 2. 实现链路

```text
OKXProvider → barsHub
  → runtime.ts（市场/收盘K/成交变化，300ms节流）
  → analyze.ts（校验、去重、闭合K线、最新连续段）
  → patterns.ts（原有价格形态几何）
  → mwStory.ts（归并形态、单一阶段/结论、六段证据）
       ├─ evidence.ts（单根覆盖、两腿比较、连续CVD、力量证据）
       └─ scenario.ts / evaluateLine（关键位、颈线各一次生命周期）
  → projectSignals（显示开关、活跃选择、历史焦点、密度限制）
  → annotLayer.ts（专用Canvas）+ SignalPanel / MwStoryDetails（完整详情）
```

`keyLevelCall.ts` 及其独立评分/阶段出口已删除。`scenario.ts` 不再组装 UI 或生成第二套结论，`analyzeMwPhase`、`analyzeKeyLevelScenario`、`selectScenarios`、`rankScenarioReads` 已移除。阶段/方向只由 `analyzeMwStory` 产生，价格生命周期由 `evaluateLine` 提供。

## 3. 形态与归并

`patterns.ts` 的价格几何未改：左8/右5根确认首次摆动；两测间隔至少8根；颈线高度至少2 ATR；先前趋势至少1.5 ATR；等高/等低容差为 `min(max(0.35 ATR, 0.04%价格), 0.7 ATR)`，扫位深度容许0.5 ATR；二测需收盘拒绝或紧接下一根确认。不使用交易成本、RR门槛隐藏视觉形态。

`groupMwPatterns` 按同侧、**形态时间区间重叠**且关键位距≤1 ATR或颈线距在容差内归并；不把不同时间段的独立形态仅因同价位强行合并。代表是最新确认的二次测试；`patternCount` 为归并描述数，`testCount` 只数这些形态里识别出的测试时间点，不声称统计了全部盘中触碰。归并的各次确认保留在时间线中。

## 4. 关键位与颈线是两条不同的线

- 外侧关键位：双顶阻力、双底支撑。向外突破会否定原反转方向，仍可跟踪该次突破的回踩/反抽。
- 颈线：双底向上、双顶向下突破的路径。
- 两条线各跑一次 `evaluateLine`，以最近的状态事件决定当前观察对象；更晚的反向关键位失效不能被旧颈线结论遮住。
- 不再按“离关键位1.5 ATR”标为已兑现。第一参考位触及后继续跟踪颈线事件；延伸参考位 `2×颈线−关键位` 必须在颈线确认后的**后续已收盘K线**中真实触达，且未先失效，才显示「延伸位已到·不追」。确认根内部的先后顺序无法由OHLC知道，不把同根极值当成确认后成交结果。

## 5. 生命周期与工程门槛

`scenario.ts` 单向遍历已收盘序列；事件记录收盘时间，不使用后来的 ATR 改写早先事件；观察带在突破确认时固定。

| 事实 / 阶段 | 实际代码条件 | 表达 |
| --- | --- | --- |
| `pending` / `break-pending` | 首根收在位外超过0.2 ATR | 待第二根；无确认方向 |
| `broken` | 时间连续的两根收盘越位 | 只确认价格破位，不自动叫“真突破” |
| `break-weak` | 确认量<1.2×，或1.2–1.5×且缺少完整同向成交 | 缩量 / 证据不足，观望 |
| `break-wait` | 确认量≥1.5×，或量≥1.2×且两根真实成交合计Δ与突破同向≥0.04；尚未触带 | 等回踩/反抽，不追；一般量不写成放量 |
| `touch` / `break-retest` | 首次高低范围与观察带相交，但未收盘重新守在突破侧，或质量不足 | 触带不等于确认 |
| `retest` / `continued` → `break-held` | 已收盘守在突破侧；回撤≤61.8%；回踩确认根量≤0.9×突破确认根 | 回踩守住/反抽受阻 |
| `failed` | 收盘回到位内超过0.2 ATR | 原突破失败；不保留旧的“守住”结论 |
| `expired` | 等待回踩48根未到，或首次触带后超过12根观察窗 | 不延伸旧区带，不重置时间冒充新突破 |

回撤按回踩确认的收盘价相对突破后极值计算，推进幅度分母至少1.5 ATR。这是现有工程度量，不是精确微观路径或预测概率。

**口径修正**：旧文案写0.3 ATR失效、执行却用0.2 ATR；现在提示与执行统一为0.2 ATR。旧回踩代码允许 `<1.2×`，与“缩量≤0.9×”说明不一致；现在严格执行≤0.9×，不满足时仅待确认。未更改原交易回测引擎的阈值。

## 6. 力量与真实成交

`readMwEvidence` 把证据固定到二次测试/确认时点：

- 第二腿/第一腿单位成交量：≤0.9缩量、>1.1放量反证。
- 测试K和确认K相对之前20根（不含当前K）的量比。
- 拒绝影线比例（≥35%）、价格扫位深度（≥0.05 ATR且收回）。
- 测试与确认的真实 taker 买/卖额、归一化Δ、来源、覆盖率。
- 吸收**候选**：量比≥2、真实推进侧Δ幅度≥0.15，但收盘位置/方向未随之推进；不声称看到被动订单或机构。
- 两腿比较要求各腿每根连续真实覆盖；CVD要求第一次极值至二测整段连续覆盖。缺任一根不拼接OHLC代理。

力量标签「较强/一般/不足/分歧」来自显式证据计数；各条支持、反证、缺失都显示，不是模型概率。没有真实成交时仍可说明价格拒绝，但不会把它说成真实买卖力量已经确认。

覆盖门槛沿用 `hasRealFlow`：tape 聚合额为K线报价币成交额的85%–110%，rubik官方统计为95%–110%。所有金额为 USDT 名义额；`buy−sell` 是 taker 主动成交差，不是订单簿OFI。原始形态仍是价格结构，局部成交来源单独标明，不把整个形态冒称全段真实成交。

## 7. 诱多 / 诱空两种形态，统一12根观察窗

1. **测试扫位型**：二测扫高/低≥0.05 ATR后收回。测试和确认均有完整覆盖，且反转侧接管，或追单方向放量但未续、确认成交支持收回，才称「诱多/诱空候选」。缺失/冲突时只描述「扫高/低收回（仅价格）」。
2. **破位后收回型**：两根收盘破位后又收回。两根突破成交完整且收回根Δ支持反向≥0.04时附成交佐证；否则只称价格假突破/假跌破。

超过12根保留历史事实，不把过去的陷阱当成当前主结论。后来的颈线事件或反向失效可取代它作为当前阶段。不存在“真实止损已触发”“已经有人被套”的事实断言。

## 8. 实时与历史的边界

- 默认只用已收盘 K 线确认阶段；未收盘价格不改主标题、方向、目标或排序。
- 开启预览后增加独立「盘中…待收盘」提示；辅助Δ预览可随条件消失撤回。
- 新收盘K可以推进阶段。这不是“永远冻结整张卡”：固定的是原始形态几何、确认时间和当时证据；新事件有独立时间。历史真实成交回补可以补齐缺失证据，但不能倒写价格确认时间。
- `signalRecomputeKey` 关注实际最新已收盘OHLC/量、根数、范围、周期边界；`flowRecomputeKey` 在预览关闭时忽略只有形成中成交变化的通知，闭合根的成交修正仍触发分析。
- WebSocket先连接，历史rubik回填不阻塞实时订阅；取消请求不进入5分钟失败冷却。中止的in-flight任务不复用，旧finally不能删除新任务。
- `/api/okx` 只经服务端代理。取消原样传播、JSON错误原样保留、HTML静态回退转503；不会因快速切币而误走浏览器直连触发CORS。
- 300ms节流、1.5秒心跳保留；收起侧栏不停止运行器。历史缺口只分析最新连续段，界面显示截断与覆盖根数。

## 9. 画布密度与历史查看

默认最多3个当前形态（买向、卖向、观望各不重复），每个一条关键位主线、可选颈线/折线、一个阶段标记；最多2块区带。同价位辅助支撑线让位于主形态。其余记录仍在列表，不是被检测器删除。

点选历史记录可替换一席进行临时聚焦；仍显示历史/失效状态，截止时间不延伸至未来。`paint:false` 现在对所有图层元素生效，不再只隐藏事件却偷偷画重复线。画布悬停只放有边界的摘要，完整数字在可滚动侧栏，避免详情卡超出屏幕。
